# 状态切换、任务、模型服务的 SSE 同步

## 同步范围

- `robot_status_changed`：模式、Teach、运动输出、急停锁、epoch、四臂/三相机在线状态。
- `job_changed`：现有任务阶段、结束、失败与单条录制结果。
- `server_changed`：模型服务加载/Ready/退出。
- 相机沿用独立 MJPEG；关节角改为下文的低频实时缓存；数据集和 checkpoint 目录不跟状态事件刷新。

## 隔离与时效

一个 Dashboard 实例共享三个后台观察线程：机器人、任务、模型。机器人每次检测后等待 0.2 秒，ZMQ 每请求超时 0.3 秒；不查 SSH、不扫目录、不读 H5、不取图像字节。
这是后端周期检测、变化推送，不是桥端原生订阅；短于检测周期的瞬时变化可能不显示，不能作为安全控制器或审计日志。

SSE 每 0.1 秒检查发送队列。机器人走独立 latest-only 通路，在任务历史前发送，不回放积压控制状态，也不占任务历史队列。任务/模型继续使用 Last-Event-ID 恢复。
状态不变时仅每秒发送轻量机器人心跳，不传连续 state。检测结果超过 1.5 秒未更新，或浏览器超过 3 秒没收到机器人通知，显示过期并禁用依赖在线状态的启动入口；SSE 断开立即失效。

手动 overview 的慢返回不覆盖最新机器人状态或低频实时关节显示。急停与清除停止锁仍是 POST 命令，不再随后触发全量扫描；网页按钮不是机器人端安全门控。

## 低频实时关节显示（同日追加）

按用户要求，四臂 J1–J6 和夹爪不再显示手动快照，改为约 2 Hz 的 `joint_state` SSE 消息。
状态检测原本就获取关节反馈：该次观测同时更新 Dashboard 进程内的一份 latest-value cache，不增加机器人查询。所有浏览器从这份缓存读取，不各自连接机器人；无图像字节、目录扫描、磁盘轮询或逐帧历史。

优先级顺序：状态切换 → 限频关节最新值 → 任务/模型通知。关节事件不写入历史队列，不影响控制状态的变化去重，也不更新运动按钮。`GET /api/robot/joints` 是鉴权的缓存只读诊断入口，不直接查询机器人。
页面标注数据年龄和单位；连续 2 秒没收到关节数据、后台缓存超龄或 SSE 断开后，保留最后数值但标为过期，不假装实时。相机链路不变。

## 验证

- 状态变化去重、最新状态独立于任务队列、慢模型探测不阻塞机器人检测、检测过期暴露。
- 探测不请求 JPEG，输出不含关节角/图像时间戳，关节运动不触发事件。
- 前端运行验证：保留手动关节快照、状态优先于慢快照、心跳不重绘、过期失效。
- 不通过自动运动或切换 Teach 来测试，不修改机器人端控制程序。
